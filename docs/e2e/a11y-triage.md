# A11y triage — Phase 2 initial sweep

Generated by `npm run e2e:a11y` (chromium-light project, light + dark color schemes) on 2026-05-12.

Coverage: 40 component `examples` pages, 2 color schemes for axe, 4 explicit assertions per page + 1 disclosure-toggle sanity check. Total ≈ 240 tests. Every entry below is a **real failure surfaced by the suite** — none are silenced via `.exclude()` and none are listed as expected.

Findings are grouped by rule, then by component, then by suggested fix and owner (library / demo / theme). Severity matches axe's `impact` field; the two explicit-assertion failure classes (`aria-controls resolves`, `form control has accessible name`) are tagged with the closest matching axe rule (`aria-valid-attr-value` / `label` respectively).

## 1. `aria-hidden-focus` — serious — every page (40 / 40)

axe: <https://dequeuniversity.com/rules/axe/4.11/aria-hidden-focus>

**Symptom.** The shell sidebar renders one `<div class="sh-submenu" aria-hidden="…">` per component group. The submenu wraps each group's child links (`Overview`, `Examples`, `API`). When a group is collapsed, the div carries `aria-hidden="true"` but the child `<a routerLink>` elements remain in the DOM and tabbable, so axe flags focusable content inside an `aria-hidden` container on every routed page.

**Owner.** Demo (`projects/demo/src/app/layout/shell.ts:369-388`).

**Suggested fix.** Either drop `aria-hidden` from `.sh-submenu` entirely (the CSS `max-height: 0; overflow: hidden` already hides it visually) and gate the child links on the same `isItemExpanded` signal with `[inert]`, or add `[attr.tabindex]="isItemExpanded(item.label) ? null : -1"` to the inner `<a>` so collapsed groups stop participating in tab order.

**Specs hitting this.** `examples.spec.ts — light scheme` and `— dark scheme` for every component.

## 2. `landmark-unique` — moderate — 37 / 40 pages

axe: <https://dequeuniversity.com/rules/axe/4.11/landmark-unique>

**Symptom.** `tw-code-block` renders `<pre role="region" aria-label="… code">` (where the suffix is the `language` input). Every demo examples page contains multiple code blocks for the same language, so axe sees several `region` landmarks sharing one accessible name.

**Owner.** Library (`projects/ngx-tw/code-block/code-block.ts`).

**Suggested fix.** Drop `role="region"` from the `<pre>`. The wrapping `tw-code-block` already provides a clear heading/language affordance and the inner `<pre>` is the focusable content — promoting it to a landmark is over-described. If a landmark is desired, switch to `role="figure"` with `aria-labelledby` pointing at the visible language tab so each name is content-derived and naturally unique. Alternatively, expose a `regionLabel` input the demo can set per-example.

**Specs hitting this.** Same as #1, minus the three pages with no code blocks (`accordion`, `dialog`, `time-picker` — verified by walking the dark-mode JSON; everywhere else fires).

---

## 3. `color-contrast` — serious — 21 / 40 pages

axe: <https://dequeuniversity.com/rules/axe/4.11/color-contrast>

**Symptom.** Several `solid` / `filled` color variants do not meet WCAG AA (4.5:1 for normal text). Sample failing pairs surfaced by axe:

- `bg-info-600` + `text-white` — alert (`<tw-alert color="info">`), badge, button, dialog
- `bg-success-600` + `text-white` — button, command-palette
- `text-info-600`, `text-success-600`, `text-warning-600`, `text-error-600` against `bg-surface-raised` — card stat counters, form-field hints, paginator counts, spinner labels
- `text-fg-subtle` on `bg-surface-muted` in dark mode — tab-nav inactive labels, segmented-control inactive labels

**Owner.** Theme (`projects/ngx-tw/theme/default.css`) primarily; component variants may also need to swap from `-600` to `-700` for solid surfaces.

**Suggested fix.** Treat as theme work. Audit `--color-info-600`, `--color-success-600`, `--color-warning-600`, `--color-error-600` against `#ffffff` and `oklch(…)` of `--color-surface-raised`; bump the 600 shade darker (or push solid variants to the 700 shade) until every color × on-color pair meets 4.5:1. Re-run `npm run e2e:a11y` to verify the matrix.

**Specs hitting this.** 21 components, light and dark.

## 4. `aria-controls` does not resolve — critical (treat as `aria-valid-attr-value` regression)

The chapter calls this out explicitly. Five components emit `aria-controls="X"` while the element with `id="X"` is conditionally rendered, so when the controlled region is closed/collapsed/inactive the reference dangles.

| Component | Source | Failure |
|---|---|---|
| `collapsible` | `projects/ngx-tw/collapsible/collapsible.ts:144` | `aria-controls` is host-bound unconditionally; panel template at `:207` is `@if (keepAlive() ? activated() : open())`, so closed-and-never-opened panels are absent from the DOM. |
| `accordion` | composes `Collapsible` | Inherits the same bug — every closed trigger refers to a missing panel id. |
| `select` | `projects/ngx-tw/select/select.ts:445` | `aria-controls="listboxId"` is set on the trigger button always; the listbox only mounts inside the CDK overlay when `open()` is true. |
| `date-picker` | `projects/ngx-tw/date-picker/date-picker.ts:285,325` | Same overlay pattern: `aria-controls` is bound to the dialog id while the overlay is unmounted. (`date-range-picker` likely has the same bug; the axe sweep didn't catch it because its trigger renders the controls only when invoked — but the static check on the open scenario would surface it, see §11.) |
| `stepper` | `@angular/cdk/stepper` | Sibling step panels are not rendered (CDK only renders the active step's content). Inactive headers carry `aria-controls="cdk-stepper-N-content-K"` for missing ids. |
| `tabs` | `projects/ngx-tw/tabs/` | Inactive tab triggers carry `aria-controls="tw-tabs-N-panel-…"` while only the active panel is in the DOM. |

**Suggested fix (uniform pattern).** Make `aria-controls` conditional on whether the target is actually mounted. The minimal change is `'[attr.aria-controls]': 'open() ? panelId : null'` for components that own the trigger, and rendering all sibling panels with `hidden`/`aria-hidden="true"` (kept in the DOM) for tabs and stepper. The collapsible-family fix should also flip `aria-expanded` and `aria-controls` together so the contract stays consistent.

**Specs hitting this.** `explicit-assertions.spec.ts — every aria-controls resolves` on accordion, collapsible, date-picker, select, stepper, tabs.

## 5. Form controls missing accessible names — critical

axe: <https://dequeuniversity.com/rules/axe/4.11/label>

| Component | Source | Failure |
|---|---|---|
| `input` (demo) | `projects/demo/src/app/routes/input/examples/` | Several bare `<input twInput id="tw-input-0">` / `<textarea twInput>` examples are rendered without a wrapping `<tw-form-field>` / `[twLabel]`, so there is no `<label for>` and no `aria-label`. |
| `paginator` (demo) | `projects/demo/src/app/routes/paginator/examples/` | `<input type="range">` "Items per page" sliders have no label or `aria-label`. |
| `toast` (demo) | `projects/demo/src/app/routes/toast/examples/` | `<input type="range">` "Duration" slider has no label or `aria-label`. |
| `select` (library) | `projects/ngx-tw/select/select.ts` trigger button | When no value is selected and no `aria-label`/`[twLabel]` is provided, the trigger renders an empty button — `button-name` fires (see §7). |

**Suggested fix.** For the three demo pages, wrap the standalone examples in `<tw-form-field>` with a `[twLabel]` or add an `aria-label` to each control. The chapter's contract is "every `<input>` / `<select>` / `tw-select` has either an associated `<label>`, a `[twLabel]` directive, or an `aria-label`" — the helper page is the simplest place to satisfy it without changing library semantics.

**Specs hitting this.** `explicit-assertions.spec.ts — every form control has an accessible name` on input, paginator, toast.

## 6. `aria-required-children` — critical — calendar, stepper

axe: <https://dequeuniversity.com/rules/axe/4.11/aria-required-children>

- **calendar** (`projects/ngx-tw/calendar/month-view.ts`): `<div role="row">` contains children without `gridcell`/`rowheader`/`columnheader` roles. The weekday header row is the most likely offender — it currently renders `<div>` cells without explicit roles.
- **stepper** (`projects/ngx-tw/stepper/`): `<div role="tablist">` contains buttons without `role="tab"`. CDK's stepper provides `role="tab"` on the underlying button, but the visible header may render an intermediate wrapper that doesn't.

**Suggested fix.** Add the missing roles directly: `role="columnheader"` on the weekday cells in calendar's month-view, `role="tab"` on the actual interactive header element in stepper. Confirm by re-running axe on `/components/calendar/examples` and `/components/stepper/examples`.

## 7. `button-name` — critical — select

axe: <https://dequeuniversity.com/rules/axe/4.11/button-name>

**Symptom.** `<button id="tw-select-15" role="combobox" aria-haspopup="listbox" aria-expanded="false">` has no text content and no `aria-label` when nothing is selected and no consumer-supplied label is set. The trigger is an unlabeled button to a screen reader.

**Owner.** Library + demo. The library should always emit an accessible name (placeholder text as content, or `aria-label` from the `[twLabel]` ancestor); the demo can avoid the failure by always wrapping `<tw-select>` in `<tw-form-field>` with `[twLabel]`.

**Suggested fix.** In `select.ts`, render the placeholder text inside the trigger button (currently the placeholder is shown via the projected template — verify it's inside the button, not a sibling). For consumers using a placeholder-only flow, that text becomes the accessible name. If a `[twLabel]` is associated via form-field, set `aria-labelledby` to the label id.

## 8. `aria-prohibited-attr` — serious — paginator, select

axe: <https://dequeuniversity.com/rules/axe/4.11/aria-prohibited-attr>

- **paginator**: `<span aria-label="More pages">` on the ellipsis. `aria-label` is prohibited on elements without an interactive or landmark role.
- **select**: `<tw-select aria-label="…">` — same problem on a custom element with no host role.

**Suggested fix.**
- paginator: remove `aria-label` from the ellipsis `<span>` and render the literal text "More pages" inside the span (visually hidden if desired with `sr-only` Tailwind class) — or give the span `role="text"` so the prohibited-attr rule no longer applies. The ellipsis is non-interactive, so just keep it as text.
- select: move `aria-label` from `<tw-select>` to the inner trigger `<button>` (which already has `role="combobox"` and accepts `aria-label`).

## 9. `aria-allowed-attr` — critical — sort, table

axe: <https://dequeuniversity.com/rules/axe/4.11/aria-allowed-attr>

**Symptom.** `<span aria-sort="ascending">` and `<span aria-sort="none">` — `aria-sort` is only allowed on elements with `role="columnheader"`/`role="rowheader"`. The `tw-sort` directive currently lives on a generic `<span>`/`<div>` that has `role="button"`.

**Suggested fix.** Apply `tw-sort-header` to a `<th>` or to an element with `role="columnheader"`; do not put `aria-sort` on a `<span>`. The simplest demo-only fix is to wrap the sort trigger in `<th>` inside a `<thead><tr>`. Long-term, the directive should refuse to bind `aria-sort` unless its host element is a column header.

## 10. `nested-interactive` — serious — sort, tabs

axe: <https://dequeuniversity.com/rules/axe/4.11/nested-interactive>

- **sort** (`projects/ngx-tw/sort/`): `<div role="button" tabindex="0">` wraps a `<button>`. Two interactives nested.
- **tabs** (`projects/ngx-tw/tabs/`): `<button role="tab">` contains a `<button aria-label="Close X">`. The close button cannot be reached by screen-reader users navigating tabs, and a keyboard `Enter` on the outer button triggers the tab change rather than the close action.

**Suggested fix.**
- sort: drop the outer `role="button"` / `tabindex="0"` and rely on the inner `<button>`. The wrapper exists for layout, not interaction.
- tabs: render the close button as a sibling of the tab trigger inside the tab `<li>` (or in a wrapper that is not itself interactive). The close button should target the tab via `aria-controls`, not be nested inside it.

---

## 11. `empty-table-header` — minor — table

axe: <https://dequeuniversity.com/rules/axe/4.11/empty-table-header>

**Symptom.** The demo table has an "actions" column whose header `<th>` is empty (the column holds row-level action buttons).

**Owner.** Demo (`projects/demo/src/app/routes/table/examples/`).

**Suggested fix.** Render an `sr-only` label inside the `<th>` — e.g. `<th scope="col"><span class="sr-only">Actions</span></th>`. axe will accept a hidden text node as a non-empty header.

## Operating rules going forward

1. The specs in `e2e/specs/03-accessibility/` stay strict. **Do not** add `exclude` selectors to "make them pass" — every exclusion masks a real regression.
2. Each finding above should turn into a focused PR. The chapter 09 phasing already plans per-component coverage (Phase 3+); these fixes can land alongside their respective component specs.
3. After a fix lands, re-run `npm run e2e:a11y` and update this document by removing the resolved entry. Keep the entries that remain — the doc is the working backlog, not a historical record.
4. New components added to the library inherit the sweep automatically (the spec iterates `COMPONENTS` from `e2e/support/routes.ts`). They must land clean against this suite before merge.
